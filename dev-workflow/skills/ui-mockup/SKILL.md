# ui-mockup

**Announce:** "ui-mockup으로 목업을 발산·선택해 UI 결정을 spec에 기결정으로 굳힙니다."

## 핵심 원칙

화면이 새로 생기거나 구성이 바뀌는 기능에서, **plan 이전에** 사용자의 시각적 취향을 목업 선택으로 확정하고 **spec에 기결정으로 기록**해 구현 단계의 임의 재해석을 막는다. 선택 결과는 **프로젝트 스타일 가이드로 수렴**시켜 기능 간 UI 파편화를 막는다.

두 가지가 이 스킬의 전부다:

1. **판정자는 사용자다.** 발산·조합·다중 화면 어느 경로로도 **사용자 확인 없이 확정되는 목업은 없다.**
2. **산출물은 파일이 아니라 기록이다.** `docs/design/<feature>/` 파일만 남기고 spec에 기록하지 않으면 3.5는 **미완료**다 — plan·구현이 그대로 재해석한다.

## 언제 / 언제 아님

```
brainstorming → spec 초안 → harden-spec → [ui-mockup (3.5, 옵션)] → review-loop(spec) → plan → 구현
```

- **쓴다:** 굳은 spec(`## 재논의 금지(기결정)` 블록 존재)이 **새 화면을 만들거나 기존 화면 구성을 바꾸고**, 아직 spec에 `## UI 설계` 기록이 없을 때.
  - **이미 `## UI 설계`가 있으면 3.5는 완료**다 — 다음 단계는 `review-loop --phase spec`이다(plan 직행·harden-spec 회귀 아님). 단 사용자가 **재선택·재발산을 명시 요청**하면 재실행하고, §절차 1의 재생성 경로(소유자 판정 + 미커밋 보존 확인)를 그대로 밟은 뒤 그 섹션을 새 결과로 갱신한다.
- **하한선:** 레이아웃 구조가 바뀌거나 새 UI 블록(섹션·패널·테이블·차트 등)이 생기는 수준부터 충족. **문구·색·아이콘·단일 컨트롤 추가 같은 경미 변경은 미충족 → 건너뛴다.** 경계가 애매하면 진입 확인 질문으로 사용자가 판정한다.
- **안 쓴다:**
  - **대상 spec이 없다**(단발 "목업 만들어줘") → 실행하지 않고 `superpowers:brainstorming` → `dev-workflow:harden-spec` 경로를 안내한다. 상태가 굳기 전 목업은 구조적으로 다시 만든다.
  - spec이 아직 굳지 않았다(재논의 금지 블록 없음) → 먼저 `harden-spec`.
  - UI가 없는 기능·경미 변경 → 건너뛴다(생략을 기록하지도 않는다 — 트리거 미충족).

## 입력

- **대상 spec 경로.** 생략 시 `docs/specs/`의 최신 파일 또는 현재 브랜치에 대응하는 spec을 찾아 확인받는다(harden-spec과 동일). `docs/specs/`가 없거나 대상이 없으면 §언제 아님의 단독 호출 경로로 간다.
- **`<feature>` 슬러그.** spec 파일명에서 날짜 접두를 제거한 값을 기본 제안한다(`2026-07-25-foo-design.md` → `foo-design`). `^[a-z0-9-]+$` **단일 경로 세그먼트만 허용** — `/`·`\`·`..`·절대경로·빈 문자열이 든 슬러그는 **거부하고 다시 받는다**.
- **산출물 경로는 `docs/design/<feature>/` 고정.** 다른 위치를 발명하지 않는다. 쓰기 대상 `docs/design/<feature>`가 **심볼릭 링크면 거부**하고 슬러그 변경을 요구한다.
- **진입 확인(AskUserQuestion 1회):** 트리거 충족 여부 + 슬러그 확정 + (기존 디렉터리가 있으면) §절차 1의 소유자 판정 결과에 따른 처리. 사용자가 **생략**을 택하면 spec의 `## 재논의 금지(기결정)`에 "UI 목업 생략(사용자 결정)" 한 줄만 기록·커밋하고 종료한다(dev-cycle·harden-spec의 3.5 재권고 차단).

## 절차 (5단계)

### 1. 로드 · 소유자 판정

spec에서 **대상 화면 목록과 핵심 상태(기본/빈/에러)** 를 추출한다 — 화면·상태를 **발명하지 않는다**(spec에 없으면 §spec 결함의 구조적 분기). 여러 화면이면 **가장 복잡한 화면을 대표 화면**으로 잡는다.

발산 모드 입력을 확인한다: `docs/design/style-guide.md` 존재 여부 + (가이드 없을 때) repo에 기존 UI(화면·템플릿·CSS)가 있는지.

`docs/design/<feature>/`가 이미 있으면 **소유자부터 판정**한다 — 그 경로를 `## UI 설계`에서 참조하는 spec을 repo에서 검색해:

| 소유자 | 처리 |
|---|---|
| **다른 spec** | 슬러그 충돌. 재사용·재생성 **금지**, **슬러그 변경만** 허용(다른 기능의 커밋된 산출물 보호). |
| **없음**(중단·잔재) | 완료로 간주하지 않는다. 진입 확인에서 **재개(기존 후보 재사용) / 재생성 / 슬러그 변경**을 묻는다. 재개면 기존 후보에 §목업 제약을 **재검증**한다. |
| **같은 spec** | 재생성 허용(산출물은 커밋돼 git 이력으로 복구 가능). 단 아래 미커밋 확인을 먼저 한다. |

**미커밋 보존 확인 (덮어쓰기 전 필수).** 재생성·덮어쓰기 전 대상 경로(`docs/design/<feature>/`·`docs/design/style-guide.md`·대상 spec)의 미커밋 변경을 `git status --porcelain <경로들>`로 확인한다. 변경이 있으면 **AskUserQuestion으로 보존 방법(선커밋 / 새 슬러그 / 중단)** 을 받은 뒤 진행한다 — 미커밋 변경은 git 이력으로 복구되지 않는다.

### 2. 발산 (가이드 수렴형)

**개수와 종류는 아래 표가 정한다.** 스스로 줄이거나 늘리지 않는다.

| 상황 | 발산 |
|---|---|
| 가이드 없음 + 기존 UI 없음(신규 프로젝트) | 서로 다른 스타일 **4종** |
| 가이드 없음 + 기존 UI 있음 | **모드를 사용자에게 묻는다**(AskUserQuestion) — **(a) 기존 디자인 유지**: 기존 UI에서 `style-guide.md` 초안을 역추출해 승인받고 "가이드 있음" 행으로 진행 / **(b) 리뉴얼**: 신규 스타일 4종(선택본이 새 가이드가 되고 이후 실행은 (a)로 수렴) |
| 가이드 있음 | 가이드 준수 **레이아웃 변형 2~3종**만. 스타일 재발산은 **사용자가 명시 요청할 때만** |

- **다중 화면 spec은 대표 화면 1개로만 발산한다.** 나머지 화면은 §절차 4에서 선택 스타일로 생성한다 — 4종 × 전 화면은 탈락안에 드는 비용 낭비다.
- 각 목업은 **기본 화면 + 핵심 상태 1~2개(빈/에러)** 를 포함한다 — harden-spec이 굳힌 상태가 시각화되는 지점.
- 파일명 `candidate-<n>.html`. **서브에이전트 병렬 생성**, 생성 에이전트에 **`model: fable`** 을 지정한다(시각 품질 — 본체는 세션 모델, 본 스킬은 model 오버라이드를 두지 않는다). `frontend-design`·`dataviz` 스킬이 설치돼 있으면 생성 에이전트가 참조하도록 지시한다.
- 발산은 **총 2라운드 상한**(초기 1 + §절차 3 전부 거부 시 재발산 1).

### 3. 제시 · 선택

- **`compare.html`** 을 함께 생성해 탭/분할로 한눈에 비교하게 한다. 후보는 **빈 `sandbox` 속성 iframe**으로 격리 임베드하고, `src`는 **같은 디렉터리의 로컬 상대 경로만**:
  ```html
  <iframe sandbox src="candidate-1.html" title="후보 1"></iframe>
  ```
- **선택은 AskUserQuestion으로 받는다.** "가장 나은 안"을 스스로 확정하지 않는다.
- **조합 지정 허용**("2번 레이아웃 + 4번 색"). 조합이면 `candidate-combo.html`을 **1회** 재생성해 `compare.html`에 추가하고, **최종 확인 1회를 받은 뒤 확정**한다 — 사용자가 고른 것은 조합 *규칙*이지 생성 *결과*가 아니다. 거부되면 **재조합이 아니라 수정 요청 루프**로 보낸다(재생성 1회 상한 유지).
- **전부 거부:** "무엇이 아쉬운지" 방향 피드백을 받아 **재발산 1회**(발산 총 2라운드 상한). 그래도 불만족이면 가장 근접한 안을 고르게 하고 수정 요청 루프로 전환한다.

### 4. 확정 · 기록

1. **다중 화면이면 나머지 화면을 지금 생성**한다(`screen-<n>-<이름>.html`, 선택 스타일). `compare.html`에 추가하고 **AskUserQuestion으로 최종 확인 1회**를 받는다(수정 요청 가능 — 재발산이 아니므로 발산 라운드에 불산입). **이 확인 전에는 spec 기록·커밋을 하지 않는다.**
2. **후보·비교 페이지를 모두 남긴다.** 탈락 시안을 삭제·정리하지 않는다 — 왜 그 안이 됐는지가 이력이다.
3. **style-guide.md 수렴**(§style-guide 수렴 규칙).
4. spec에 **`## UI 설계`** 섹션을 추가한다: **확정 슬러그 + 선택 목업 경로 + 핵심 결정 요약**. 이 섹션이 **3.5 완료 레코드**이며 dev-cycle 판별 기준이다(디렉터리 존재가 아니다).
5. spec의 **`## 재논의 금지(기결정)` 블록에 UI 결정을 기록**한다 — review-loop·plan·구현의 재해석을 기결정 가드로 차단(harden-spec과 같은 메커니즘).

**완료 = 위 기록 + §절차 5 커밋까지.** design 파일만 있고 spec 기록이 없으면 미완료(§절차 1 재개 경로).

### 5. 종료

- **커밋:** design 파일 + spec만 **명시적으로 stage 후 커밋**한다.
  - `git add -A` 금지(무관한 untracked·다른 세션 작업 혼입).
  - `.git/index.lock`이 있으면 다른 세션이 git 사용 중 — 지우지 말고 기다린다.
  - 커밋 메시지에 AI 서명/도구 흔적 금지(글로벌 규칙).
- **정지:** `review-loop --phase spec`을 권고하고 멈춘다. 자동 전환하지 않는다(단계 경계 = 새 세션 + `/clear`).

## 목업 제약 (허용 목록 — 허용 외 전부 거부)

목업은 자체완결 **비실행** HTML이다. **허용되는 것만 쓴다:**

- 정적 마크업
- 인라인 CSS(`<style>` 블록 또는 `style` 속성)
- 정적 인라인 SVG

**그 외 활성 콘텐츠·외부 참조는 전부 거부한다** — 금지 목록을 외워 피하는 게 아니라, 허용 3종에 없으면 쓰지 않는다. 자주 새는 곳: `<script>`, `on*` 이벤트 핸들러, `<form action>`/submit, `<object>`·`<embed>`, meta refresh, `javascript:`·`data:` 같은 실행성/원격 URL, 외부 CDN·웹폰트·`<link rel=stylesheet>`·원격 이미지. 이미지가 필요하면 인라인 SVG나 CSS 도형으로 대체한다.

- **`<iframe>`은 `compare.html`의 후보 임베드에서만** 쓰고, 반드시 빈 `sandbox` + 같은 디렉터리 상대 경로 `src`다.
- 생성 직후 각 후보를 이 기준으로 검증한다. **재개(§절차 1)로 기존 후보를 재사용할 때도 재검증**하고, 위반 후보는 재생성하거나 제외한다.
- 인터랙션(툴팁·탭 전환·호버 차트)은 **정적 상태 여러 컷**으로 표현한다 — 스크립트로 구현하지 않는다.

## style-guide 수렴 규칙

- **첫 실행(가이드 없음):** 선택 결과(또는 역추출 승인본)에서 `docs/design/style-guide.md`를 생성한다 — 색·타이포·간격·컴포넌트 규칙.
- **이후 실행:** 가이드에 없는 **새 컴포넌트 규칙만 증분 추가**한다(living document — 기존 규칙의 변경·삭제는 하지 않는다).
- **명시 요청 재발산으로 다른 스타일이 선택되면:** 가이드를 새 선택으로 **교체**한다(이전 가이드는 git 이력에 보존). 기존 화면과의 불일치는 확정 시점에 **잔여 리스크로 기록**한다.
- **동시 변경 가드:** 가이드를 쓰기 **직전에 `style-guide.md`를 다시 읽는다**. 로드 시점과 달라졌으면(다른 세션·작업의 변경) **최신 내용 기준으로 증분 추가를 재적용**한다. 커밋은 이 실행이 만든 파일만 명시 stage.

## 목업 중 spec 결함 발견 시 (경중 분기)

목업 작업이 `## UI 설계` 밖의 spec 변경을 요구하면:

- **경미**(굳힌 화면 목록 안에서 상태 1~2개 보강 수준) → 사용자 확인 후 이 세션에서 spec에 직접 반영하고 계속 진행.
- **구조적**(화면 추가·요구 변경) → **중단하고 `harden-spec` 재실행을 권고**한다. 3.5가 제2 brainstorming이 되지 않게 한다.

## 합리화 (전부 무효)

| 합리화 | 실제 |
|---|---|
| "요청에 산출물·스타일·수량이 이미 담겼으니 spec 없이 만들어도 된다" | 입력은 요청 문장이 아니라 **굳은 spec의 화면·상태 목록**이다. 상태 확정 전 목업은 구조적으로 다시 만든다 → 거부하고 brainstorming → harden-spec 안내. |
| "주제가 명확하니 화면을 추론해서 만들자" | 화면·상태를 발명하지 않는다. spec에 없으면 harden-spec의 일이다. |
| "차트 툴팁·탭 전환 정도는 목업 품질에 필요하다" | 목업은 비실행이다. 인터랙션은 **정적 상태 여러 컷**으로 표현한다(§목업 제약 허용 목록). |
| "가장 나은 안이 분명하니 그걸로 확정하자" | 판정자는 사용자다. 선택은 **AskUserQuestion**. |
| "3종이면 충분하다 / 왕복을 줄이려 개수를 조정한다" | 개수는 §발산 표가 정한다. |
| "선택을 1회로 끝내려면 전 화면 × 전 상태를 모든 시안에 담아야 한다" | **대표 화면 1개만** 발산한다 — 탈락안에 드는 비용을 없앤다. 나머지 화면은 확정 후 생성 + 최종 확인. |
| "탈락 시안은 확정 후 정리(삭제)한다" | 후보·비교 페이지까지 **커밋한다** — 왜 그 안이 됐는지가 이력이다. |
| "목업 디렉터리 README에 결정을 적으면 기록은 끝" | 완료 레코드는 spec **`## UI 설계` + 재논의 금지 블록**이다. spec에 없으면 plan·구현이 재해석한다. |
| "`mockups/`·`docs/mockups/<날짜-슬러그>/`가 더 자연스럽다" | 경로는 **`docs/design/<feature>/` 고정**이다. dev-cycle·plan·review-loop가 이 경로를 본다. |
| "가이드가 있지만 더 나은 스타일도 보여주고 싶다" | 가이드 있음 = **레이아웃 변형 2~3종**. 스타일 재발산은 사용자 명시 요청 시만. |
| "디렉터리가 이미 있으니 3.5는 끝났다" | 완료 판정 기준은 spec `## UI 설계` + 커밋이다. 디렉터리만 있으면 **재개 경로**다. |
| "같은 spec이니 그냥 재생성해서 덮어쓰자" | 덮어쓰기 전 **미커밋 변경 확인**이 필수다. 커밋된 것만 git으로 돌아온다. |
| "조합은 사용자가 지정했으니 결과 확인은 생략해도 된다" | 지정된 것은 **조합 규칙**이고, 확인 대상은 **생성 결과**다. 최종 확인 1회 후 확정. |

## 하지 말 것 (red flags — 멈추고 자기점검)

- 트리거 미충족(UI 없음·경미 변경)인데 목업을 만든다 → 건너뛴다.
- **spec 없이 단독 목업**을 만든다 → 거부하고 brainstorming → harden-spec 안내.
- 가이드가 있는데 스타일 4종을 재발산한다 → 레이아웃 변형만(재발산은 명시 요청 시).
- 기존 UI가 있는 프로젝트에서 감지 없이 4종 자유 발산한다 → 유지(역추출)/리뉴얼 **모드 선택을 먼저** 받는다.
- **선택을 안 받고** 목업을 확정한다(조합본·다중 화면 나머지 포함) → 전부 AskUserQuestion.
- 전부 거부에 재발산을 반복한다 → 재발산 1회(총 2라운드), 이후 수정 요청 루프.
- UI 결정을 spec에 기록하지 않고 목업 파일만 남긴다 → **재논의 금지 블록까지가 산출물**.
- 목업에 script·이벤트 핸들러·form 제출·외부 리소스를 넣거나, 비교 페이지에 후보를 **sandbox 없이** 임베드한다 → §목업 제약.
- 슬러그에 경로 구분자·`..`·절대경로를 허용하거나, **심링크 디렉터리에 쓴다** → 거부하고 슬러그를 다시 받는다.
- 다른 spec이 소유한 디렉터리를 재사용·덮어쓴다 → 슬러그 변경만.
- 미커밋 변경을 확인 없이 덮어쓴다 → 보존 방법을 먼저 확인한다.
- 목업이 끝나자 plan으로 넘어간다 → **review-loop(spec) 권고 후 정지**.
- `git add -A`로 커밋하거나 **AI 서명**을 넣는다 → 명시 stage + no-AI-trace.

## 인자

- (선택) 대상 spec 경로/슬러그. 생략 시 자동 탐색 + 확인.
