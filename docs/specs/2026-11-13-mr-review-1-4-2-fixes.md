## 3. 항목별 명세

### 3.ⓑ cleanup 결과의 워크트리 표기

**현상**: `cleanup` 첫 줄 `CLEANED worktree=<true|false> zip=… raw=… masked=… extra=…`. `false` 는 세 경우에 똑같이 나온다 — diff-only(워크트리가 원래 없음) · 사용자가 미리 지움 · 같은 `W` 에 cleanup 재실행. 읽는 쪽(메인 세션·사람)은 「지우기 실패」와 구분하지 못한다.

**원인**(조회 사실 `report.mjs:628-635`·`:808`): `worktree` 는 호출 시점에 워크트리 디렉터리가 **있어서 지웠으면** `true`, 없었으면 `false` 인 불리언이고 그대로 출력된다. 삭제가 실패하면 예외로 끝나므로(`fs.rmSync` 가 던진다) `false` 가 「실패」인 경우는 없다 — 표기가 그 사실을 말해 주지 않을 뿐이다.

**수정**
1. 값을 두 낱말로 바꾼다: **`worktree=removed`**(이 호출이 워크트리 디렉터리를 지웠다) · **`worktree=absent`**(지울 워크트리 디렉터리가 없었다 — diff-only · 이미 지워짐 · 재실행). 판정 조건은 현행과 같다(호출 시점 디렉터리 존재 여부) — **동작 불변, 표기만**.
2. `cleanup()` 반환 객체의 `worktree` 칸도 같은 문자열(`'removed'|'absent'`)로 바꾼다(조회 사실: 호출자 = `cmdCleanup` 과 테스트뿐 — `report.mjs:806` · `tests/mr-review/report.test.mjs`).
3. 첫 줄의 나머지 칸(`zip=`·`raw=`·`masked=`·`extra=`)·둘째 줄(`extra: …`)·`ERR` 경로 — 불변.
4. SKILL.md §8 의 `CLEANED worktree=<b> …` 문구를 `worktree=<removed|absent>` 로 바꾸고 한 구절을 붙인다: 「`absent` = 지울 워크트리가 없었다(diff-only · 이미 지워짐) — 실패가 아니다」.

**AC**
- ACⓑ-1 워크트리 모드 · `W/worktree` 있음 → 첫 줄 `CLEANED worktree=removed …` · 디렉터리 없음.
- ACⓑ-2 워크트리 모드 `snapshot.json` 인데 디렉터리가 이미 없음(사용자가 지운 실사례) → `worktree=absent` · exit 0 · 나머지 정리(zip·raw·masked·extra)는 현행대로 수행.
- ACⓑ-3 diff-only → `worktree=absent`.
- ACⓑ-4 같은 `W` 에 cleanup 2회 → 첫째 `removed` · 둘째 `absent`.
- ACⓑ-5 기존 테스트의 `CLEANED` 기대 문자열은 `worktree=` 값만 바뀐다(`report.test.mjs:403` `false` → `absent` · `:444` `true` → `removed` — **명시 예외**, 다른 칸 값 불변).
- ACⓑ-6 SKILL.md 문구 테스트(`report.test.mjs:861`)가 새 문구(`worktree=<removed|absent>`)를 단언한다.

### 3.ⓔ `merge` 패스 3 — 넓은 발견이 다른 사안을 삼킴

**현상**: 두 검토자의 발견이 「같은 `file` + `intentRows` 가 **하나라도** 겹침」이면 패스 3 이 합친다. 검증 표 행을 여러 개 건 넓은 발견은 같은 파일의 거의 모든 발견과 겹친다 → 서로 다른 사안이 한 발견(`source: both` · `joinedBy: intentRows`)이 되고, 단독 출처였다면 받았을 `needsMain`(「단독 출처 낮은 확신 차단」·「단독 출처 설계 내 수정 가능 판단」)이 생기지 않는다. 잘못 합친 것은 첫 줄 수치(`joined=`)에만 묻어 있어 메인이 놓치기 쉽다. 반대로 합치지 **않은** 같은 파일 쌍은 `candidates`(D138)로 보인다 — 덜 합치는 쪽은 눈에 보이고 잘못 합치는 쪽은 보이지 않는다.

**원인**(조회 사실 `merge.mjs:74-86`): 패스 3 조건 = `inter(c.rws, x.rws).length > 0 && c.f.file != null && c.f.file === x.f.file`. 교집합 크기만 보고 두 묶음이 얼마나 다른지는 보지 않는다. 패스 안은 claude 배열 순 → 아직 짝 없는 codex 첫 것(greedy)이라, 넓은 발견이 앞에 있으면 먼저 가져간다.

**수정**(D150 — **D137 의 패스 3 조건 변경**)
1. 패스 3 조건 = 두 발견의 `intentRows` 묶음이 **비어 있지 않고 서로 같다**(원소 집합 동치 — 순서·중복 무관) **그리고** `file` 이 같다(둘 다 `null` 아님). 비교하는 묶음은 현행과 같은 값이다 — `--rows n` 이 있으면 1~n 밖 번호를 걸러 내고 중복을 없앤 뒤(`rws`).
2. 그 밖은 전부 불변: 패스 순서(0 `--same` → 1 지문 → 2 `decisionIds` → 3) · 패스 안 순서(claude 배열 순 → 짝 없는 codex 첫 것) · 1:1(D136) · 한 번 짝 지은 발견은 다음 패스에서 다시 쓰지 않음 · `joinedBy` 의 값 이름 `intentRows`(값 집합 불변 — SC-5 스키마·`validateFindings`·부록 D 불변).
3. 후보 규칙(D138)은 불변이고 새 코드도 없다 — 일부만 겹치는 같은 파일 쌍은 패스 3 에서 합쳐지지 않으므로 현행 규칙 ⓐ 로 `(같은 파일 <경로>)` 후보가 된다(조회 사실 `merge.mjs:126-136`). 메인이 같은 사안으로 판단하면 지금처럼 `merge --force --same claude:<i>=codex:<j>`.
4. SKILL.md §6-1 의 (다) 문구를 「`intentRows` 묶음이 같음(비어 있지 않음) **그리고** 같은 `file`」로 바꾼다. §6 ⓒ(후보 판단 → `--same`)·허용 칸 목록은 불변.

**AC**
- ACⓔ-1(실사례 재현): claude `[DESIGN_DRIFT · file p · 행 1~11]` + codex `[MISSING_EVIDENCE · file p · 행 5]` → `joined=0` · 두 발견 모두 단독(`source: claude`·`codex`) · `candidates: claude:1~codex:1(같은 파일 p)` · `mergeCandidates [{ pair: ["F1","F2"], why: "같은 파일" }]`. 현행 코드에서는 `joined=1`(RED).
- ACⓔ-2 같은 묶음: `[13]` ↔ `[13]` · 같은 파일 → 합침(`joinedBy: intentRows`). `[5, 6]` ↔ `[6, 5, 5]` → 합침(순서·중복 무관).
- ACⓔ-3 일부 겹침: `[13]` ↔ `[13, 14]` · 같은 파일 → 합치지 않음 + `(같은 파일 …)` 후보.
- ACⓔ-4 `--rows` 로 걸러 낸 뒤 비교: `--rows 20` · claude `[5, 99]` ↔ codex `[5]` → 같음 → 합침. 걸러 낸 뒤 둘 다 빈 묶음(`[99]` ↔ `[98]`)은 합치지 않는다.
- ACⓔ-5 같은 묶음 · 다른 파일 → 합치지 않음 + `(같은 행 n)` 후보(D138 — 현행 유지).
- ACⓔ-6 ACⓔ-1 의 입력에 `--force --same claude:1=codex:1` → 합침(`joinedBy: same` — 메인이 일부러 합치는 길은 그대로).
- ACⓔ-7 단독 출처 확인이 살아난다: ACⓔ-1 에서 codex 발견이 `confidence: medium` 이면 `needsMain` 에 그 발견의 「단독 출처 낮은 확신 차단」이 있다(현행 코드에서는 없음 — RED).
- ACⓔ-8 결정성: 같은 입력을 다른 순서로 넣어도 `findings.json` 바이트 동일(1.4.0 AC③-1 유지).
- ACⓔ-9 기존 `merge.test.mjs` 전부 불변(조회 사실: 기존 패스 3 픽스처는 행 묶음이 같은 쌍뿐 — `merge.test.mjs:46`·`:74`·`:78`. impl 에서 실행으로 확인).

**검증 필요(실측)**
