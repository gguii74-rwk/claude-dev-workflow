## 1. 배경 · 목표

1.3.5 설치본(어댑터 v1.1 — 공통 필수 렌즈 + 순서 분산 · 코드 주 검토자 = Codex)으로 **같은 head 의 큰 구현 MR 1건**(정식 트랙 · 24파일)을 2026-10-24 오전에 네 번째로 돌렸다(1.3.1 → 1.3.2 → 1.3.3 → 1.3.5, 같은 head). 네 실행을 나란히 놓으면:

- **핵심 결함**(기준선 결정 「조회는 남은 허용 상태와 상관없이 매번 비밀번호 요구」 vs 코드 = 남은 확인 상태만으로 개인정보 조회 API 가 응답)을 **Codex 2/4 · Claude 2/4 · 둘 중 하나라도 3/4** 만 잡았다. 1.3.5 실행은 Codex 깊이 표지가 정상(변경 24 중 12 언급 · 명령 38회 · `weak:false`)인데도 놓쳤다 → 깊이(1.3.5 ①)가 아니라 **「기준선 결정 ↔ 코드」 대조를 강제하는 출력이 없는 것**이 원인 가설.
- 같은 결함의 **`fixableInDesign`** 이 1.3.3(두 모델 모두 `no` → RETURN_TO_DESIGN)과 1.3.5(Claude 단독 `yes` → CHANGES_REQUESTED)에서 갈려 **검토자 1명의 한 단어가 판정 단계를 정했다**.
- 같은 사안을 두 모델이 다른 파일·제목·유형(DEFECT ↔ MISSING_EVIDENCE · MISSING_EVIDENCE ↔ FOLLOW_UP)으로 내 **지문(파일 + 정규화 제목)이 안 맞아 메인이 손으로 합쳤고**, 의도 대조표 34행 병합·검증 표 행 수 세기도 즉석 스크립트였다 — 팀원 공유를 앞두고 실행자마다 결과가 달라질 위험.
- **운영 함정**: 1.3.5 를 설치한 뒤 떠 있던 세션(/clear 포함)이 스킬 로더로 1.3.2 「Base directory」를 띄웠다(mr-review·orchestrate 둘 다). 모르고 돌리면 고쳐진 결함이 그대로인 옛 버전으로 리뷰한다.

메인이 정리한 개선점 7건 중 ⑤(다른 저장소 사본 파일을 어댑터가 모름)는 프로젝트 어댑터 v1.3 으로 처리돼 범위 밖이고, 사용자가 이번 범위를 **①·②·⑦ + ③**(Q1 — D113)으로 정했다. ④(위키 발췌 관련성)·⑥(리포트 중복 문장)은 비목표(후속 후보). 우선순위 = ① > ② > ⑦ > ③(③ 은 ① 의 「사안 키」와 같이 설계해 비용이 작다).

예시는 전부 가상 값이다(프로젝트 `alpha` · MR `!66` · head `e5e5e5e` · 기준선 1차 spec `docs/specs/2026-10-06-account-verify-design.md`(결정 D1·D3) · 2차 spec `docs/specs/2026-10-12-info-download-design.md`(결정 D4) · 코드 `src/main/java/com/example/alpha/account/AccountController.java:357`). 이 저장소는 공개 repo 다(D10) — 리뷰 대상 프로젝트·저장소 이름·호스트·사람 이름·계정은 spec·코드·테스트 어디에도 적지 않는다(SC-7 T6). 실행 수치(4회 · 2/4 · 24파일 · 12 언급 · 38회 · 34행)는 그대로 쓴다(프로젝트 식별이 아니다).

**목표**

- G1(①). 검토자 출력에 **기준선 결정 대조표**(`decisions`)가 생겨, 기준선 문서의 결정 항목마다 지켜짐(KEPT)/어김(VIOLATED)/모름(UNKNOWN) + 코드 위치를 **빈칸 없이** 내게 한다 — 의도 대조표(`intent`, 검증 표 행 기준)와 같은 방식. 결정 목록은 **스크립트가 기준선 원문에서 뽑아 번호를 매긴다**(두 검토자가 같은 번호 목록을 본다 → 번호로 병합). 판정 계산 불변(대조표는 판정 입력이 아니다 — 어김은 검토자가 finding 으로도 낸다, 어김인데 finding 이 없으면 메인 확인 대상).
- G2(②). **단독 출처**(한 모델만 잡은) 차단 DEFECT·DESIGN_DRIFT 의 `fixableInDesign` 은 「검토자 1명의 주장」으로 다뤄 **메인이 코드·기준선으로 판단**하고, 못 하면 지금의 상충 처리와 같이 「판정 미확정」 3갈래로 리뷰어에게 간다. 스크립트도 스킬도 엄한 쪽을 자동 선택하지 않는다(D9 불변).
- G3(③). 검토자 출력에 **사안 키**(`decisionIds` · `intentRows`)를 넣고, 새 서브커맨드 **`merge`** 가 두 결과를 결정적으로 합쳐 `findings.json` 초안을 쓴다. 사람 판단이 필요한 칸만 `needsMain` 으로 남겨 메인이 채우고, `verdict` 는 미처리 항목이 남아 있으면 `ERR`(fail-closed). 제목 유사도 병합은 하지 않는다(1.3.5 비목표 ⑦ 유지 — 키로 해소).
- G4(⑦). 스킬 §0 전제 확인에서 **띄운 스킬 폴더(Base directory) ↔ 설치 기록(`installed_plugins.json`) 불일치**를 검사해 다르면 **멈추고** 세션 재시작을 안내한다. mr-review 만(다른 스킬 공통화는 후속 트랙).

## 6. 잔여 리스크 · 미해결 질문(harden 대상)

**미해결 질문(설계 세부 — 이 세션이 빌더 결정으로 적었고 3 harden-spec 에서 압박한다)**

- H-a ① 결정 추출 기본 규칙 ⓐⓑⓒ 의 범위 — 「수용기준 번호(`AC-3`·`V13`)」 같은 다른 번호 체계는 기본 규칙에 넣지 않았다(어댑터 패턴 몫). 기존 저장소 기준선의 실제 꼴(표 vs 목록 vs 제목)에 맞는지 실측 전이다.
- H-b ① 결정 목록 블록의 위치(기준선 출처 본문 **앞**)와 `line` 표기 — Codex 가 「(12행)」을 보고 원문을 찾는 데 충분한가.
- H-c ① `decisions` 를 **필수 배열**로 둔 것(빼먹으면 INVALID → 단일 모델 모드) — 검토자 준수율이 낮으면 교차 검토가 자주 사라진다. 대안 = 선택 + 「누락」 표시.
- H-d ① `decisionGaps` 를 `needsMain` 으로만 두고 판정 입력에서 뺀 것(D9) — 메인이 「UNKNOWN 으로 정정」을 남용하면 대조표가 무력화된다. `decided` 근거 1줄이 유일한 감사 흔적.
- H-e ② 단독 출처 **high** 확신 DEFECT 도 `fixableInDesign:null` 초안으로 메인 판단을 강제한 것 — 메인 작업량 증가 vs 판정 흔들림 방지. `confidence` 로 나누지 않았다.
- H-f ③ 1:1 greedy 짝 짓기(claude 순 → codex 첫 일치) — 세 발견이 한 사안인 경우(claude 1 · codex 2) 하나는 단독으로 남는다(`candidates` 로 보임). 전이 폐포는 과병합 위험으로 택하지 않았다.
- H-g ③ (다) 규칙에 `file` 같음을 요구한 것 — 검증 표 행이 같고 파일이 다른 두 발견(문서 ↔ 코드)이 같은 사안일 수 있다(`candidates` 는 `file` 같을 때만 뜬다 — 이 경우 메인이 못 본다). 대안 = (다) 를 `candidates` 로만.
- H-h ③ `needsMain` 미처리 → `verdict ERR`(fail-closed) — 재실행(`--resolve`)·재리뷰 경로에서 1.3.5 이전 `findings.json`(키 없음)과의 공존 규칙은 「키 없음 = 검사 없음」으로 두었다.
- H-i ③ `criterion` = 검토자 값(D122) — 리포트 표에 검토자 제말이 들어간다. 프롬프트 「원문 그대로」 지시의 준수율은 실측 전.
- H-j ⑦ 적용 엔트리 순위(`projectPath === $PWD → user → managed`)가 Claude Code 의 실제 스코프 우선순위와 같은가(repo 밖 사실 — companion 해소 블록과 같은 가정).
- H-k ⑦ 「Base directory」가 캐시 밖(`SKILL_DEV`)이면 비교를 생략하는 것 — 개발 체크아웃을 막지 않으려는 선택이지만, 사용자가 임의 경로에 플러그인을 두는 설치 방식이 있으면 거기서는 감지가 없다.
- H-l 버전 1.4.0 으로 가면서 README·marketplace 의 「1.3.x 패치 줄」 관행과 다른 줄 형식이 필요한가(impl 몫 — 형식만).

**검증 필요(실측 — repo 조회로도 사용자 결정으로도 닫히지 않는 외부 사실)**

- ③ `findings.json` 을 메인이 손으로 바꾸는 길은 금지 문구로만 막는다(기계 강제는 `needsMain`·`blocking:null`·`validateFindings` 범위).
