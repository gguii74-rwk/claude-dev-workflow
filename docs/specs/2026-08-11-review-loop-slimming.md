# review-loop 감량 (slimming) — 실측 근거 없는 규칙 삭제 + 재비대 방지

- 단계: **1–2 브레인스토밍·spec 초안 완료 (2026-08-11) — 다음 = 3 harden-spec** (새 세션). 종결 시 이 줄을 갱신할 것.
- 배경: 브리프 프로그램(순번 1~8) 종결 직후의 독립 트랙. 입력 = Fable 교차검증 보고서 `~/workspace/dev-workflow-eval/report/XVAL-2026-08-11.md`(repo 밖 — 게이트에 필요한 내용은 이 문서에 자체 수록) + 규칙별 입증 대조 인벤토리(같은 세션 산출, §4 표가 원본 요지).
- 대상: `dev-workflow/skills/review-loop/SKILL.md` (0.15.0 기준 **449줄 / 71.8KB** — 0.7.1은 19.6KB, ×3.7). 목표 릴리스 **0.16.0**.
- 경로: **경량 예정**(브레인스토밍 세션 사용자 승인 2026-08-11 — 세션 한정 규약상 harden 세션 재확인 필요) · 5 plan·6 plan 검증 생략 예정(harden에서 D기록 승격) · **4 spec 적대검증 정식 실행** · impl ledger = 이 문서 말미.
- 후속 연계: 감량판(0.16.0)이 A/B 실측 트랙(별도)의 B arm이 된다. 감량 후 실측 순서는 2026-08-11 사용자 결정.

## 1. 문제 (실측 근거)

review-loop 문면이 0.7.1 19.6KB → 0.15.0 71.8KB(×3.7)로 팽창했으나, 규칙별 입증 대조(XVAL §7) 결과 실측 근거가 있는 것은 일부다:

- **PROVEN ≈ 45%** — 실패 실측 → 도입 → 소멸 실측이 있는 규칙(가드 focus 재지목 400회/92파일→0 · 2모드 확인 부채 78파일→0 · score 산식 거짓 정체 실측 등). 유지.
- **MOTIVATED ≈ 33%** — 동기는 실재, 효과 실측 없음. 이번 트랙 비대상(차기 압축 후보).
- **SPECULATIVE ≈ 13% (~9.5KB)** — 실사고 0인 예방 규칙.
- **순수 중복 ≈ 8~9% (~5.5KB)** — 본문 재서술·요약 이중화. fp-I14(0.15.0 impl 계열의 선행 실측)가 "요약·본문 불일치가 결함을 만든다"를 실증 — 중복은 무해하지 않고 유지 비용이 실측된 부채다.

루프 자체의 자기 복잡도 생산 경향(XVAL C3 — 수정→후속 finding 연쇄가 전 트랙에서 재현)과 결합하면, 근거 없는 규칙은 방치 시 계속 늘어난다. 삭제와 함께 재비대 방지 장치가 필요하다.

## 2. 목표

1. SPECULATIVE 규칙 삭제(~9.5KB) + 순수 중복 제거(~5.5KB) — **표적 약 15KB(전체의 1/5)**. 수치는 인벤토리 추정치이며 하드 게이트가 아니다 — 게이트는 §4 목록의 전 항목 처리(삭제 또는 근거 있는 잔류 기록)다.
2. 재비대 방지 3건 추가(~5줄) — §5.
3. 행동 무회귀 — 기존 GREEN arm 전건 유지(§6).
4. 릴리스 0.16.0.

## 3. 범위 / 비목표

- **범위**: `dev-workflow/skills/review-loop/SKILL.md` 단일 + 릴리스 부속(plugin.json 범프·README 3종 대조).
- **비목표**: 다른 스킬(dev-cycle 등) 감량 · MOTIVATED 산문 압축(~4KB — 차기 후보, 이번엔 손대지 않음) · ESCALATE batch 기계 자체의 변경(사용자 기결정 "무해라 유지" 존중 — 삭제 대상은 flush 세부 문장뿐) · A/B 실측(후속 트랙) · 훅 스크립트 변경 · README 내용 개편(대조·동기만).

## 6. 검증 (writing-skills TDD — G-e 필수, 8단계 게이트 갈음)

- **웨이브별 게이트**: 각 웨이브 완료 시 기존 GREEN arm 재실행 → 전건 GREEN이어야 다음 웨이브 진입. RED 시 카테고리 커밋 단위 역추적.
- **기존 arm 재실행(무회귀 축)**: 영향권 = 가드 focus 계열 · 핸드오프/복원 계열(7c L-1~L-5) · 2모드 전환·확인 계열. 하네스 재사용 = `.remember/harness-7c/`·`.remember/harness-8/`(+ 필요 시 재생성 명령은 `.remember/remember.md` §하네스). 정확한 영향권 arm 목록·런 예산은 harden에서 확정(§9-③).
- **신규 arm(대체 문구 축, 3종 내외)**: ⓐ 폴백② 대체 1줄 — 재개 세션이 확인 1회를 수행하는가 ⓑ 요약 블록 삭제 후 종료 판정 정답 유지 ⓒ D14 삭제 후 기결정 가드 무회귀. 파일럿 1런 + 본배치 arm당 5런 이상(브리프 §0-2 승계).
- **RED의 의미**: 이 트랙은 삭제 트랙이라 "결함 재현 RED"가 아니라 **삭제 전·후 동일 arm 비교의 무회귀 검증**이 본질이다. 신규 arm ⓐ~ⓒ는 삭제 후 문면의 GREEN 기준.
