## 1. 문제

**(0) 운영 배경 — 메인 세션 오케스트레이터(2026-10-17 실측, 1.1.0 spec §1(0)의 연장).** ops-hub와 이 repo 모두 메인 세션이 트랙 세션을 오르카 터미널로 띄우고 감시하며 질문에 답하는 운영이다. 1.1.0은 그 운영을 위해 세션 모드(수동/위임)와 위임 모드 효과 1(후계 자동 인계 끄기)을 넣었고, 효과 2는 §7 후속으로 남겼다. 2026-10-17 메인 세션(맥북)이 1.1.0 트랙 4~9단계·AC6과 1.1.1 트랙 전 단계를 이 방식으로 운영한 기록:

- **실제 흐름(4단계)** — ① 트랙 터미널 생성(`orca terminal create --worktree path:<abs> --title <트랙명> --command 'claude … --model <id>' --json` → 핸들) → tui-idle 대기 → 긴 지시는 `.remember/track-*.prompt` 파일로 쓰고 「이 파일을 읽고 그 지시대로 진행하라」 한 줄만 전송(`--enter --wait-submit 15`, `turn_started` 확인). ② 감시 — 즉석 스크립트(`watch.py`): 20초마다 렌더링 화면(`--screen`)을 읽어 프롬프트 박스 위 본문의 해시가 **바뀐 뒤 다시 안정 + tui-idle**이면 SETTLED, 「Enter to select」·「to navigate」가 보이면 QUESTION. ③ 질문 처리 — 화면을 읽고 단계별 라우팅 → 사용자에게 AskUserQuestion(글로벌 질문 형식으로 재작성) → TUI 키 입력. ④ 단계 종료 — 트랙의 보고를 메인이 **직접 검증**(`git log origin/main..HEAD` · 테스트 재실행 · AI 서명 grep · diff 범위) → (사용자 지시가 있을 때만) push → claude-memories에 핸드오프·메모리 커밋 → 보고 → 단계 경계에서 정지.
- **적용한 질문 라우팅** — 사람·취향 단계(브레인스토밍·harden-spec·ui-mockup): 모든 질문을 사용자에게(추천이 트랙·메인 동일해도). review-loop(spec)부터: 위험군(critical·보안·방향 전제·AC·목표 조정·비가역)만 사용자, 그 외는 추천안(첫 선택지)을 메인이 골라 전달. 공개 배포(push)·다른 머신 환경 변경(plugin update)·외부 실측은 매번 사용자 확인(승인은 다음 단계로 이월하지 않음). **결과: 사용자에게 전달한 질문 약 20건 전부 추천안 채택(번복 0) · 메인 대리 채택 1건.**
- **재현된 함정(10)** — (f1) `terminal wait --for tui-idle`은 트랙이 codex 백그라운드 대기로 턴을 끝내면 즉시 satisfied → 「진행 중 대기」와 「완료」를 구분 못 함(본문 변화+안정으로 판정해야 했다). (f2) 기본 `terminal read`(누적 스트림)는 claude TUI에서 1줄 조각만 → `--screen` 필수. (f3) AskUserQuestion TUI: 단일 질문 = 커서가 첫 선택지(추천)라 Enter만. 묶음 = Tab(`\t`) 다음 탭 · Shift-Tab(`\e[Z`) 이전 · 각 탭 Enter = 선택+다음 · 마지막 「Review your answers → Submit answers」 Enter. 다른 탭을 읽으려면 Tab으로 넘겨 읽고 Shift-Tab 복귀. (f4) `--dangerously-skip-permissions`여도 `sh -c` 안 `rm`은 「could not be checked」 확인 창이 떴고 무인 세션은 약 1분 30초 뒤 자동 거부 예정이었다(사용자가 직접 승인) → 오케스트레이터가 감지·전달해야 하는 화면 유형. (f5) 플러그인 user 스코프 갱신으로 project 스코프(ops-hub)는 같이 오르지 않는다 — 실측 전 `~/.claude/plugins/installed_plugins.json`으로 해당 경로 버전 확인. (f6) `claude plugin update --scope user` 직후 대기 중이던 트랙 세션이 종료(원인 미확정) → `--resume <세션 id>`로 새 터미널에 이어 붙여 복구. (f7) 종료된 터미널에 send하면 셸에 텍스트가 들어갈 위험 → send 전 `terminal show`의 연결 상태 확인. (f8) 트랙이 메인 프롬프트의 사실 오류(미push 여부 등)를 스스로 정정한 사례 2건 → 메인 프롬프트는 사실을 git에서 확인해 쓸 것. (f9) 메인이 트랙에 `/model`을 보내자 **「새 세션 기본값으로 저장」되어 사용자 전역 `settings.json`의 model이 Fable로 바뀌어 되돌렸다** → 트랙 모델은 기동 명령의 `--model`로만. (f10) 사용자가 트랙 터미널의 질문 창에 **직접 답한 사례 여러 번** → 메인이 감시로 QUESTION을 잡은 시점과 키를 보내는 시점 사이에 창이 닫혔거나 탭 상태가 바뀌어 있을 수 있다. 다른 머신 실측은 맥북 오르카의 spark2 페어링(`--environment spark2-ts`)으로 원격 터미널 생성·읽기·전송이 됐다.

**(a) 오케스트레이터 절차가 플러그인 밖에만 있다.** 위 흐름·라우팅·함정은 메인 세션의 브리프 문면(`.remember/main-2026-10-17-mode-track.md`)과 즉석 스크립트에만 있다 — 다음 메인 세션은 다시 짜야 하고(f1·f2는 매번 재발견), 브리프 문면 의존이라 사실 오류(f8)가 트랙에 흘러간다. ops-hub 쪽은 `orca-worktree-ops` 스킬 + CLAUDE.md 규칙 #1~#9에 **프로젝트 고유** 부분(repo id·브랜치 개명·워크트리 삭제·Windows 경로·모델 배분)이 있지만, 머신·프로젝트 공통인 「트랙 기동 → 감시 → 질문 라우팅 → 검증·push → 핸드오프 → 후계 → 페어링」은 어디에도 규약으로 없다.

**(b) 위임 모드에서 위험군 외 질문도 사람 손(메인의 TUI 조작)을 탄다.** 1.1.0 위임 효과는 훅 1개(후계 인계)뿐이라, 위임 트랙의 batch ESCALATE·진행 질문은 여전히 AskUserQuestion으로 떠서 메인이 감시로 잡아 추천을 골라 Enter를 누른다. 실측상 이 결정들은 추천 수용 102/107(ops-hub) · 번복률 2.4%(핵심층) · 배포 후 결함 0인데, 매번 메인의 감시 턴 + 조작 턴이 든다. 그리고 그렇게 닫힌 **무인 결정의 기록 형식이 없다** — UNATTENDED §0 분기 ①의 뜻은 자율화 확대가 아니라 「확인 대기 대장 규약화」(무인 결정을 감사 가능한 형식으로 표준화)다.

- 다중 트랙은 **허용하되 같은 체크아웃에 둘은 금지**(H20, §3o ⑤) — 그 이상의 다중 트랙 조율(우선순위·의존 DAG)은 범위 밖.
- 번복률 측정 자체(eval repo 몫 — 대장은 그 측정의 입력 형식). Windows 오르카 실측. 오르카 외 터미널(tmux 등) 감시 지원. doctor 변경(스킬 존재 여부 점검 추가 없음).

## 3. 설계

### 3o. `orchestrate` 스킬 — 메인 세션용 공통 절차

- **호출**: `/dev-workflow:orchestrate <트랙 설명·단계·spec 경로>`. description 트리거 예 — 「트랙 띄워」「메인 세션으로 돌려」「이 단계 위임으로 진행해」「트랙 감시해」「후계 띄워」. **오탐 방지 문구**(doctor 패턴): review-loop 안 codex 실패(review-loop 몫) · 단일 세션에서 직접 하는 작업 · 오르카 CLI 자체 사용법 질문(`orca-cli` 몫) · 워크트리 생성·삭제 정책(프로젝트 규약 몫)에는 트리거하지 않는다. frontmatter에 모델 고정 없음(F4).
- **시작 자가 점검(H21)**: 메인 세션 자신의 `DEV_WORKFLOW_MODE`를 셸로 읽어 `delegated`면 「이 세션은 위임 모드라 메인 역할에 부적합(자기 후계를 띄우지 못한다 — 1.1.0 D8·D9)」을 1줄 경고하고 계속 여부를 AskUserQuestion 1회(기본 = 중단 권고).
- **역할 규칙**: 메인은 **spec·plan·코드를 편집하지 않는다**(트랙 몫) — 손대는 파일 = 핸드오프(`.remember/remember.md`)·트랙 프롬프트 파일·메모리뿐(M1). 사용자에게 묻는 질문은 전부 글로벌 질문 형식(① 무슨 일 ② 예: ③ 선택지별 결과 ④ 추천 첫 선택지). 트랙이 띄운 질문을 전달할 때는 **그 형식으로 재작성**한다(트랙 문면을 그대로 복사하지 않는다 — 읽는 사람은 트랙 화면을 보지 않았다).
- **프로젝트 규약 우선**(B1): repo id · 브랜치 규칙·개명 · 워크트리 정책(같은 체크아웃 vs 워크트리) · 브리프 파일 위치(`.dev/brief.md` vs `.remember/track-*.prompt`) · Windows 경로·따옴표 함정 · 모델 배분 · 수동 트랙 권한 플래그는 **그 프로젝트 문서(CLAUDE.md·프로젝트 스킬)가 정한다**. 스킬은 「프로젝트 규약이 있으면 그것, 없으면 아래 기본값」 구조로 쓴다. 기본값 = 같은 체크아웃(워크트리 없음) · 프롬프트 파일 `.remember/track-<slug>.prompt`.
- **트랙 모델(B14)**: **기동 명령의 `--model`로만** 지정한다. 단계별 배분 기본값 = 브레인스토밍·spec 초안·harden-spec = **Fable**(`claude-fable-5-1`) / ui-mockup·plan·적대검증(review-loop)·impl·운영(릴리스·실측) = **Opus**(`claude-opus-5-5`) — 프로젝트 규약이 다른 배분을 두면 그것. **트랙에 `/model`을 보내지 않는다** — `/model`은 「새 세션 기본값으로 저장」되어 사용자 전역 `settings.json`의 `model`을 바꾼다(f9 실사고). 모델을 바꿔야 하면 그 단계의 새 트랙을 `--model`로 띄운다.
- **절차 ① 트랙 기동** — (1) **설치 버전 확인(H11)**: 그 체크아웃에 적용되는 dev-workflow 설치 버전을 스코프별로 **조회만** 한다(`~/.claude/plugins/installed_plugins.json` 또는 그 세션에서 `doctor` — 형식이 바뀌면 doctor로). 1.2.0 미만이면 사용자에게 갱신을 **제안**(환경 변경 = 사용자 확인 행 — 자동 실행 금지)하거나, 거절 시 라우팅표 3행(구버전 운영)으로 진행한다고 명시. **같은 체크아웃에 이미 트랙이 있으면 두 번째를 띄우지 않는다**(H20 — 워크트리(프로젝트 규약) 또는 순차 권고). (2) 단계 → 모드 결정표: 브레인스토밍·harden-spec·ui-mockup = **수동**(접두 없음, 질문 전부 사용자) / review-loop(spec)부터 = **위임**(`DEV_WORKFLOW_MODE=delegated` 접두) — 사용자가 수동을 지정하면 그대로. (3) **기동 명령 기본 문면(B18·H10)**: 위임 트랙 = `DEV_WORKFLOW_MODE=delegated claude --dangerously-skip-permissions --model <id> --session-id <uuid>` — 위임 모드의 정의가 「사람 없이 진행」이라 권한 창을 누를 사람이 없다(안전장치 = 프롬프트의 push 금지·비가역 금지 지시 + 라우팅표 「사용자 확인」 행 + 권한 창은 사람만 허용(H5), README 경고 1줄). 수동 트랙(사람 단계) = `claude --model <id> --session-id <uuid>`를 기본으로 하되 **권한 우회 플래그는 프로젝트 규약이 정한 대로, 규약이 침묵하면 기동 직전 사용자에게 1회 묻는다**(H10 — 추천 = 포함: 사람이 있는 시간이라 감독 가능; 같은 프로젝트에서 답이 반복되면 규약에 적으라고 안내). **세션 id는 메인이 기동 때 정한다**(`--session-id <uuid>`, M12 — F1 실측 확인) → 핸들·제목·세션 id·워크트리 경로·단계·**트랙 프롬프트 경로·모드(수동/위임)·모델 id·`--environment` 이름(로컬이면 없음)**을 핸드오프에 적는다(**현재 핸들·현재 세션 id는 후계·재획득·복구마다 갱신** — ⑤). (4) **프롬프트 = 템플릿 `templates/track-prompt.md` 빈칸 채우기(H22)** — 필수 항목: 역할 · 읽을 파일 · 기결정(다시 묻지 말 것) · 진행 범위(어느 단계까지) · 정지 조건(push 금지·다음 단계 시작 금지·비가역 금지) · 넛지 시 행동 · **review-loop 단계면 호출 인자 4종 명시(`--phase`·`--security`·`--auto-rounds`·`--base` — 보안 판정은 기동 전 사용자에게 1회 확인 뒤)(H17)** · **종료 표지·일시중단 표지 지시(H9·H16)** · 「사실은 git에서 확인해 쓴다」(f8: HEAD·push 여부·spec 경로·설치 버전). (5) 터미널 생성(`orca terminal create --worktree path:<abs> --title <트랙명> --command '<기동 명령>' --json` — 본문에 허용된 1줄 예시, H18) → 핸들 확보(= 생성 응답의 핸들뿐. 응답이 유실되면 **제목으로 찾지 않는다** — 탭 제목은 셸·claude가 덮어쓴다(훅 (2-1)과 같은 규칙). 생성 전후 핸들 집합 차분은 보고용 후보일 뿐 채택하지 않고, 재생성·전송 없이 후보를 사용자에게 보고하고 멈춘다) → tui-idle 대기 → 포인터 한 줄 전송 → `turn_started` 확인(없으면 재전송 금지 — `orca-cli`의 `--retry-request` 규칙). 나머지 명령 상세는 `orca-cli`와 스크립트.
- **절차 ② 감시** — `node <Base directory>/scripts/orchestrate.mjs watch <핸들> [최대초=580] [--consumed <마지막 처리 표지 줄>] [--environment <이름>]`을 **백그라운드로 1회** 실행하고 결과로 깨어난다(짧은 간격 폴링 턴을 메인이 직접 돌리지 않는다). `<Base directory>` = 스킬 로드 때 표시되는 「Base directory for this skill」 경로(M14 — 메인 세션 cwd는 프로젝트 repo라 상대 경로로는 못 찾는다; 1.1.1 AC8이 같은 표시를 실측). 출력 = 첫 줄 판정 **`DONE | HANDOFF | SETTLED | QUESTION | PERMISSION | TIMEOUT | ERR`**(7종) + 마지막 N줄 화면. 판정 뒤 행동표: **DONE**(H9 — 화면에 `[TRACK-DONE <단계> <HEAD>]`) → 절차 ④ / **HANDOFF**(H16 — `[TRACK-HANDOFF <재개 파일 경로>]`) → 절차 ⑤(a) / SETTLED → 화면을 읽고 판독(표지 없이 끝난 종료 보고·중간 정착·fail-closed 보고(§3e) 등 — 종료면 ④, 아니면 재감시) / QUESTION → 절차 ③ / **PERMISSION** → 사용자가 있으면 **즉시 전달**(f4 — 무인 자동 거부 전 ≈90초, 실측 1건), **사용자 부재면 건드리지 않는다 — 자동 거부되게 두고** 트랙의 후속 보고를 기다려 아침 보고에 싣는다(H5 — 권한 우회 플래그를 켜고도 뜨는 창은 정의상 위험군; 대장 행 아님 — 채택한 것이 없다) / TIMEOUT → **먼저 `alive`**(감시 중 claude가 종료돼 셸만 남으면 표지 없이 TIMEOUT만 반복된다): exit 0 → 재감시(10분 넘게 본문 무변화면 화면을 그대로 사용자에게 보고) · exit 1 → ⑤(e) 종료 복구 · exit 3 → ⑤(b) 식별 규칙으로 재획득 · exit 2 → 복구 없이 사용자 보고 / ERR → 메시지대로(스크립트 자가 점검 실패면 `orca-cli` 참조해 스크립트 갱신 — 수동 감시로 폴백하지 말고 사용자에게 보고).
- **절차 ③ 질문 처리** — 라우팅표:

  | 트랙 단계 | 질문 종류 | 누가 답하나 |
  |---|---|---|
  | 수동 트랙 — 사람·취향 단계 **및 사용자가 수동으로 지정한 review-loop 이후 단계**(R6-3) | 전부 | **사용자**(메인이 재작성해 전달, 답을 TUI에 입력 — 대리 채택 없음) |
  | review-loop부터(위임 트랙) | 위험군(§3e) · 기결정 변경(애매 포함) · **확인 감사 이의 항목(질문 문면 `[감사 이의]` 표지, H7)** · 권한 프롬프트 | **사용자** |
  | review-loop부터(위임 트랙) | 그 외 | 트랙이 효과 2로 이미 닫는다 — 메인은 화면만 확인. 그래도 TUI 질문이 떠 있으면(1.2.0 미만 설치본·효과 2 밖 질문) 추천안(첫 선택지) 선택. 감사 규칙은 **기동 프롬프트의 고정 문구(§3t 대리 채택 줄)로 루프 실행 전에 이미 적용**돼 있고(R5-1 사용자 판정 — 선택 뒤 지시만으로는 루프가 그 지시를 받기 전에 감사 제외·확인 생략을 결정할 수 있다), 선택 뒤 1줄은 재확인용이다 — 「이 답은 사용자 판정이 아니라 메인 대리 채택이다: ledger 출처 `추천 자동 채택(위임)` · `[자동 채택(위임)]` 표시 · 확인 임무 ③ 우선 감사 대상 · 확인 첨부물 ⑥(감사 제외 목록)에 넣지 말 것 · 대장 행 · 감사 이의 재질문 앞에 `[감사 이의]`」(구버전 review-loop는 사용자가 닫은 ESCALATE를 감사에서 빼므로 이 지시가 없으면 무인 판정이 감사를 건너뛴다 — §3e 감사 지위 승계) |
  | 어느 단계든 | push · 다른 머신 환경 변경(plugin update 등) · 외부 실측 · 비가역 | **사용자**(매번 — 승인 이월 없음) |

  다중 트랙 운영 중에는 사용자에게 올리는 질문·보고에 **「[트랙명 단계]」 접두**를 붙인다(H20). TUI 키 표(f3): 단일 질문 = Enter(커서 = 첫 선택지 = 추천) · 묶음 = Tab/Shift-Tab 이동 · 탭마다 Enter · Review → Submit Enter · Other(자유 서술) = 해당 선택지로 이동 후 Enter → 텍스트 → Enter. **다른 선택지를 고를 때는 화살표로 이동 후 Enter**. 키 전송은 `orchestrate.mjs key <핸들> <enter|tab|shift-tab|up|down|text …>`로 한다(M13 — Tab `\t`·Shift-Tab `\e[Z`·화살표 같은 제어 시퀀스와 `terminal send` 사용법은 `orca-cli`에도 없는 상세라 스크립트 1곳에 둔다; SKILL.md 본문은 키 이름만 쓴다).
  **입력 직전 2중 확인(B15·B16)**: (a) `orchestrate.mjs alive <핸들>`(내부 = `terminal show`의 연결·쓰기 가능 플래그 — F2: `connected`·`writable`·`orphaned` — **와 화면의 claude 입력 상태**, §3w)로 터미널과 **claude 세션이** 살아 있는지 확인 — 종료된 터미널이나 claude가 끝나고 셸만 남은 터미널에 send하면 텍스트가 셸로 들어간다(f7). 종료·stale이면 절차 ⑤(e)로 복구한 뒤 다시 감시. **(a)는 질문 키뿐 아니라 모든 전송**(포인터 프롬프트·대장 답 전달·「상태를 보고하라」 등) 직전에 적용한다. (b) 화면을 **다시 읽어** 질문 창이 **아직 열려 있고** 탭 체크 표시·커서 위치가 예상(감시가 잡은 시점)과 같은지 확인한 뒤에만 키를 보낸다 — 사용자가 트랙 터미널에서 직접 답했을 수 있다(f10). 다르면 키를 보내지 않고 현 화면 기준으로 다시 판단한다(이미 닫혔으면 재감시).
- **절차 ④ 단계 종료** — DONE(또는 SETTLED 판독으로 종료 확인) 뒤 메인이 **직접 검증**: (a) 커밋 범위 `git log --oneline <기준>..HEAD`가 보고(및 표지의 `<HEAD>`)와 일치 (b) 테스트·게이트 재실행(프로젝트 규약의 명령 — 이 repo면 훅 테스트 11/11·2/2 + `node --test tests/orchestrate/orchestrate.test.mjs`) (c) AI 서명·트레일러 grep 0건 (d) diff가 spec 대상 파일 안 (e) **확인 대기 대장의 대기 항목**(§3l) — **트랙의 ledger 문서 전부(spec + plan)**(H6). 보고를 사용자에게 올리되 **대장 대기 항목을 글로벌 형식 질문으로 함께** 묻고(전부 확인 / 번복 n건), 답을 트랙에 전달해 트랙이 대장 상태를 갱신·커밋한다(메인 편집 금지 유지). **확인과 번복을 구분한다(R3-2 사용자 판정)** — 「확인」 = 대장 상태 열만 갱신(메인은 그 커밋 diff가 대장 절만 건드렸는지 확인). 「번복」(내용 변경)이 1건이라도 있으면 **그 단계는 미완료**: 트랙이 그 phase의 수정 규칙(impl = TDD+게이트, spec/plan = 관문 재확인)으로 고쳐 커밋하고 대장 행을 `번복 (<날짜>) → <처리 커밋>`으로 갱신 → 메인이 **최종 HEAD로 (a)~(e)를 다시 검증**한 뒤에야 단계 완료·push. 번복 수정분의 소멸 확인은 **다음 phase 리뷰 루프가 필수 확인 항목으로 승계**(§3e §0 1줄 — 그 루프의 미확인 FIXED 큐), 다음 리뷰 루프가 없는 단계(impl → 릴리스)는 **새 세션 확인 라운드 1회**(review-loop 폴백② 구조)를 거친 뒤 릴리스. 사용자 부재면 대기로 남긴다. push·plugin update·외부 실측은 사용자 확인 뒤에만. 핸드오프 = `.remember/remember.md` 맨 위 블록 추가(기존 블록 보존, **트랙별 블록** — 현재 핸들·제목·현재 세션 id·워크트리 경로·단계·트랙 프롬프트 경로·모드·권한 플래그·모델 id·environment·대장 대기 수·마지막 처리 표지) + 메모리 → claude-memories 커밋(프로젝트 규약에 따라 push). **단계 경계에서 정지** — 다음 단계는 사용자 지시로 새 트랙(절차 ①).
- **절차 ⑤ 후계·재획득·페어링·다중 트랙** — (a) **HANDOFF**(위임 트랙의 일시중단, `[TRACK-HANDOFF <경로>]`): 표지 바로 위 **사유 줄**(§3t — `넛지 | 사용자 중단 | 폴백②`)을 읽는다. **사유가 넛지일 때만** 아래 후계 절차로 자동 재개한다 — 사용자 중단·폴백②·사유 불명은 후계를 띄우지 않고 사용자에게 보고한 뒤 명시적 재개 지시를 기다린다(review-loop §2i 순서 3 — 사용자가 멈추기로 한 직후 자동으로 이어가면 사람 게이트를 넘는다). 후계 절차는 **옛 세션 종료가 먼저**다: (1) 이 폴더의 codex 잡(queued/running) 0 확인 — 0이 아니거나 판독 불가면 보류·사용자 보고(옛 세션의 SessionEnd가 폴더 공유 codex 브로커를 내려 잡을 죽인다 — 훅 후계 프롬프트 「0번째 동작 — 공유 브로커 단일 실행권 검사」와 같은 조건·같은 상태 파일 직접 읽기) → (2) 옛 터미널에 `/exit` 전송 → claude 종료·셸 복귀 확인 → close(어느 단계든 실패·모호하면 후계를 만들지 않고 보고) → (3) **그 뒤에** 같은 기동 명령(접두·권한 플래그·`--model`)·새 `--session-id`로 새 터미널 생성 + 프롬프트 = 「**원래 트랙 프롬프트 파일 `<트랙 프롬프트 경로>`를 먼저 읽고 그 역할·진행 범위·정지 조건·표지 규약을 그대로 따르라.** 그다음 `<경로>`(루프 파일 `.remember/loop-*.md` 또는 `.remember/remember.md`)를 읽고 `/review-loop --resume`(해당 시)로 이어가라」(§3t 후계 줄 — 루프 파일·핸드오프에는 정지 조건·표지 규약이 없어 재개 파일만 주면 후계가 트랙 규약을 잃는다). 트랙 프롬프트 파일은 **트랙 종결까지 지우지 않는다**. 후계 생성 뒤 핸드오프 트랙별 블록의 **현재 핸들·현재 세션 id를 후계 값으로 갱신**한다(옛 값은 이력 1줄 — (e) 복구가 옛 세션을 재개하지 않게). 옛 터미널은 트랙이 스스로 닫지 않는다(핸들 둘에 동시 전송 금지). (b) 트랙이 수동 모드(1.0.x 설치본 포함)로 자가 인계했으면 옛 핸들이 사라진다 → **제목으로 고르지 않는다**(① (5)와 같은 규칙). 재획득 = 목록의 새 핸들 중 화면에 **식별 문자열**(1.0.0 후계 프롬프트의 「옛 세션(핸들 <옛 핸들>)」 또는 메인이 그 트랙에 보낸 프롬프트 파일 경로 포인터)이 보이는 터미널이 **정확히 1개**일 때만 채택 — 0개·2개 이상이면 전송하지 않고 후보를 사용자에게 보고. 채택한 자가 인계 후계에게 보내는 첫 전송 = 「트랙 프롬프트 파일 `<경로>`를 다시 읽고 그 정지 조건·표지 규약을 따르라. 그다음 상태를 보고하라」(1.0.0 후계 프롬프트는 트랙 규약을 담지 않는다). 재획득 뒤 현재 핸들을 갱신하고, 세션 id는 메인이 정하지 않았으므로 「세션 id 미상」으로 기록한다 — 그 트랙의 (e) 복구는 `--resume`을 하지 않고 사용자 보고. (c) **메인 자신의 후계**(메인은 수동 — 자기 후계는 1.0.0 자동 인계): 후계 메인은 핸드오프 트랙별 블록의 **environment·모드·권한 플래그·모델·트랙 프롬프트 경로를 먼저 복원**한 뒤(원격 트랙의 핸들은 그 environment에서만 조회된다) 적힌 **트랙 핸들**로 `terminal list`에서 재획득한다(제목은 표시용 — 식별에 쓰지 않는다; 핸들이 없거나 stale이면 (b) 식별 규칙) — 핸드오프에 **트랙별 블록**을 반드시 적는다. 메인 컨텍스트 비용 상한 규칙은 두지 않는다(H14 — 자동 인계가 안전망, 오늘 8회 정상). (d) 다른 머신: 오르카 페어링 환경(`--environment <이름>` — 이름은 프로젝트·환경 인벤토리 규약) 접두를 모든 orca 호출과 스크립트 서브커맨드에 같이 준다. **메인의 파일·git 작업은 트랙의 호스트·체크아웃에 바인딩한다**(R6-2 — `.remember/`는 머신 간 비동기화): 설치 상태 조회 · 트랙 프롬프트 파일 작성과 **포인터 전송 전 존재 확인** · ④ 종료 검증(git log·게이트·AI 서명 grep·diff·대장 읽기) · ⑤(a) codex 잡 상태 조회는 모두 ssh(별칭은 인벤토리)로 **그 호스트의 트랙 체크아웃 경로에서** 실행한다 — 메인 로컬 체크아웃의 HEAD·파일·잡 상태로 원격 트랙을 판정하지 않는다. (e) **트랙 세션의 예기치 않은 종료**(f6 — B15): `alive`가 **종료**(종료·미연결·고아 — exit 1)를 보이면 새 터미널(같은 기동 명령 — 접두·권한 플래그·`--model`)에서 `claude --resume <세션 id>`로 이어 붙인다. **stale 핸들(exit 3 — 오르카 재시작 뒤 핸들 변경)은 종료가 아니다** — 세션이 새 핸들로 살아 있을 수 있어 `--resume`하면 같은 세션이 둘 된다 → (b) 식별 규칙으로 재획득을 먼저 하고, 식별 불가면 사용자 보고 — 세션 id = 핸드오프 트랙별 블록의 **최신** 현재 세션 id(「미상」이면 복구하지 않고 사용자 보고); 복구 뒤 현재 핸들 갱신. 복구 뒤 첫 전송은 「상태를 보고하라」 한 줄로 현재 위치를 확인하고 진행한다. (f) **다중 트랙(H20)**: 트랙마다 워크트리가 다르면 동시 운영 가능 — 규칙 3줄 = 핸들별 `watch` 백그라운드 병행 · 사용자에게 올리는 질문·보고에 「[트랙명 단계]」 접두 · 핸드오프 트랙별 블록. **같은 체크아웃에 트랙 둘은 금지**(커밋 경합) — 워크트리는 프로젝트 규약.
- **분량 상한**(M3): SKILL.md ≤ 15KB(dev-cycle 수준) — 함정 목록은 1줄씩, 오르카 상세는 스크립트로, 고정 문구는 템플릿으로, 프로젝트 고유는 포인터로. L1(규약은 실측 뒤 성장) — 이번 분량은 오늘 실측 1일분으로 방어 가능한 범위까지만.
- **`$N` 금지**(1.1.1 D3 승계): SKILL.md 본문·셸 블록·템플릿에 맨 `$`+숫자를 쓰지 않는다(`${N}`·`$(N)`·서술로).

- **위험군 정의(B10)** = review-loop 즉시군 ①②③ + 「추천안이 AC·목표·비목표·D블록 기결정을 바꾼다」. **판정 규칙(H15)**: 추천안이 AC·목표·비목표·D블록 **문구를 고치거나 그 뜻을 좁히거나 넓히면** 「바꾼다」로 본다. **확신이 없으면 묻는다**(fail-closed). 1.1.0 §7의 「비가역」은 즉시군 ②에 포함.
- **기록(3곳)**: (1) ledger 행의 disposition 뒤 출처 `(추천 자동 채택(위임))` — 현행 `(사용자 ○○)`·`(루프 판정)` 표기와 같은 자리. (2) `## 확인 대기 대장`에 행 1개(§3l). (3) §4 종료 요약에 1줄 「추천 자동 채택(위임) N건(감사 미수행 m건) — 대장 참조 / 해당 없음」. 보안 판정 1줄(1.1.0 D1)은 그대로.
- **감사 지위(B17) = 루프 직접 판정과 동격.** 자동 채택 항목은 `[루프 판정]`과 같은 방식으로 **`[자동 채택(위임)]` 표시**를 달아 다음 라운드 focus에 싣고, **확인 라운드 임무 ③ 우선 감사 대상**으로 ledger에 기록한다. 확인 프롬프트 첨부물 ⑥(감사 제외 = 사용자 기결정 목록)에 **넣지 않는다**. 감사가 이의하면 그 항목은 **위험군 여부와 무관하게 사람에게**(ESCALATE — 확인 모드 예외대로 즉시, 오케스트레이터 경유 사용자) 간다 — 같은 항목을 다시 자동 채택하지 않는다. **그 재질문의 `question` 앞에 `[감사 이의]` 표지**를 붙인다(H7 — 수동 모드도 같은 표지; 오케스트레이터 라우팅표 사용자 행). **재판정 결과는 같은 fingerprint의 대장 행에 즉시 반영한다** — 유지면 `확인 (<날짜>, 감사 이의 재판정)`, 바꾸면 `번복 (<날짜>, 감사 이의 재판정) → <처리 커밋>`(수정은 이 루프의 FIXED 경로 — 미확인 FIXED 큐, 소멸 확인 뒤 `· 확인됨(<라운드>)`). 단계 종료 질문(§3o ④)은 `확인 대기` 행만 묻는다 — 폐기된 선택지를 다시 묻지 않는다. §4 루프 건강의 사람개입률 분모에서 자동 채택은 **사용자 개입으로 세지 않는다**(감사 이의 뒤 사용자 재판정이 있을 때만 센다). 근거: UNATTENDED 번복 3건이 전부 「루프 ACCEPTED → 확인 감사 이의 → 사용자 FIXED」 — 번복률 2.4%의 신뢰 근거가 이 감사다.
- **루프 시작(§0·§1)에 1줄 추가**: **트랙의 ledger 문서 전부(spec + plan 엔트리포인트)**의 대장에 `확인 대기` 행이 있으면(H6) — 수동 모드는 **리뷰 전에 사용자에게 먼저 묻는다**(항목별 확인/번복, 글로벌 형식) · 위임 모드는 그대로 진행하고 시작 요약에 「대장 대기 n건 승계」 1줄(B11 — 다음 세션 안전망). 번복 처리는 그 단계 몫(수정 = 그 라운드 FIXED 경로). 또 대장의 `번복 … → <처리 커밋>` 중 **확인 미기록 행**(단계 종료 때 번복 — §3o ④)은 수동·위임 무관하게 이 루프의 **미확인 FIXED 큐에 승계**한다(원 지적 = 대장 질문 요지 + 처리 커밋 diff) — 확인 라운드가 소멸을 확인하면 행 끝에 `· 확인됨(<라운드>)`.
- **§2i 순서 3 · 핸드오프**: 루프 파일 `## 현재`에 「자동 채택 건수」를 더하지 않는다(대장이 단일 원본 — 복제 금지 원칙). 재개 세션은 대장을 읽는다. 일시중단 뒤 `[TRACK-HANDOFF <루프 파일>]` 표지는 **트랙 프롬프트 규약**(§3t)이지 review-loop 문면 변경이 아니다.
- **`--auto-rounds`·batch 적재 규약 무변경** — 위임이어도 batch는 적재되고 전환 시점에 일괄 제시된다(그때 답을 트랙이 낼 뿐). 이 분리가 측정 근거(102/107은 batch 일괄 제시의 답)와 일치한다.

### 3l. 확인 대기 대장

- **위치(B8)**: ledger가 있는 문서(spec/plan) **말미**, 그 문서의 모든 `## 적대검증 ledger (<phase>)` 절 뒤에 **문서당 1절** `## 확인 대기 대장`(그 문서 ledger의 phase들 공통 — 행에 phase를 적는다). plan을 두는 트랙은 ledger 문서가 둘(spec → spec 문서 · plan·impl → plan 엔트리포인트)이라 대장도 둘이다(M7 — B8 「spec/plan 말미」 문면 그대로). **읽는 규칙(H6)**: 다음 단계 세션의 안전망(§3e §0 1줄) · dev-cycle 판별 출력 · 오케스트레이터 절차 ④(e)는 모두 **트랙의 ledger 문서 전부**(spec + 있으면 plan 엔트리포인트 — plan 엔트리포인트가 spec 경로를 가리킨다)를 읽는다. 복제 금지 — 대기 행을 다른 문서로 옮겨 적지 않는다(상태 열이 있는 원본 1곳).
- **행 형식**: `| # | 일시 | phase·지점 | 질문 요지(쉬운 말 1줄) | 채택 선택지 | 출처 | 상태 |` — 출처 = `추천 자동 채택(위임)` 고정(이 절에 들어오는 행은 전부 무인 결정). 상태 = `확인 대기` → `확인 (<날짜>, <경로: 단계 종료 보고 | 다음 세션 시작 | 트랙 종결 보고 | 감사 이의 재판정>)` 또는 `번복 (<날짜>[, 감사 이의 재판정]) → <처리 커밋>`(감사 이의 재판정은 §3e 감사 지위 — 루프 안에서 즉시 반영; 소멸 확인 뒤 `· 확인됨(<라운드>)` — §3e §0). finding 기원 행은 fingerprint를 질문 요지 끝 괄호에. fail-closed 보고-멈춤은 대장 행이 없다(§3e — 파일 무변경).
- **기록 주체**: 자동 채택한 그 세션(트랙)이 **그 라운드 ledger 커밋에 함께** 적는다(별도 커밋 아님). dev-cycle 경로 판정 행은 그 판정을 한 세션이 spec에 적는다(§3d).
- **닫기(B11)**: ① 단계 종료 때 오케스트레이터가 보고에 대기 항목을 싣고 사용자 답을 받아 트랙에 전달 → 트랙이 상태 갱신·커밋. ② 사용자 부재면 대기로 남고, **다음 단계 세션이 시작 때 읽는다**(review-loop §0 — 수동 = 먼저 묻기, 위임 = 그대로 진행; dev-cycle 판별 출력에 「대장 대기 n건」 1줄 — M8). 릴리스 뒤까지 남은 대기 항목은 트랙 종결 보고에서 사용자가 닫는다(M9).
- **상한·정리 규칙 없음(H12)** — ledger와 동일 취급(감사 원본 + §7 재측정 입력). 비대가 실제로 문제되면 후속.
- **용도**: 감사(무엇을 누가 언제 자동으로 닫았나) + 번복률 재측정 입력(§7). 대장이 비면 절은 「해당 없음」 1줄.

### 3d. dev-cycle — 위임 모드 = 확인 불가 신호 ②의 공식 입력
