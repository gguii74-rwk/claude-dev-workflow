- **C-3** — `review-loop` §finding ledger의 ledger 위치를 phase별로 명시하고 planless 예외(D17)를 흡수한다.
- **C-4** — `review-loop` §2i의 핸드오프를 **4섹션 골격**으로 표준화하고, 공유 파일 덮어쓰기 전 보존 확인을 넣는다.

## 3. 설계 확정 (harden-spec 2026-08-09 · D1~D21)

### C-3. impl ledger 위치 — phase별 명시

`review-loop/SKILL.md` §finding ledger `:83`의 "해당 phase 산출물 문서 말미"를 phase별 표로 바꾼다.

| phase | ledger 위치 |
|---|---|
| spec | spec 문서 말미 |
| plan | **plan 엔트리포인트 말미** (task 파일이 아니다) |
| impl | **plan 엔트리포인트 말미** (plan ledger와 같은 문서, 섹션만 다름) — **plan을 생략한 트랙은 spec 문서 말미** |

- impl에 자체 산출물 문서가 없다는 것이 모호함의 원인이므로, "impl의 phase 산출물 문서 = plan 엔트리포인트"를 명시한다. **엔트리포인트 = `docs/plans/YYYY-MM-DD-<feature>.md`** (writing-plans-split §구조 — task 파일은 `<feature>/task-NN-<slug>.md`).
- planless 예외는 C-6 D17의 흡수다. 단일 원본·복제 금지 규정은 현행 그대로 유지한다.
- **D7. 진행 중 승격으로 plan이 생겨도 impl ledger는 spec 말미에 그대로 둔다** — 이동하지 않는다. 새 plan 엔트리포인트에서는 참조만 한다. 단일 원본 규정과 정합하고, 진행 중 이동은 복제·유실 위험을 만든다.
- **D8. 비소급** — 이 개정은 개정 이후 착수한 트랙부터 적용한다. 기존 트랙의 ledger 위치는 그대로 인정하고 루프 게이트가 결함으로 지적하지 않는다(dev-cycle 0.11.0의 비소급 래퍼와 동형).

### C-4. 핸드오프 4섹션 골격 + 전용 파일 분리

`review-loop/SKILL.md` §2i를 개정한다. **D12. 섹션 명칭은 ops-hub 런북 원문을 그대로 쓴다**(실무 문서와 즉시 호환).

**D29. 루프 핸드오프는 트랙별 전용 파일 `.remember/loop-<slug>.md`에 둔다 — 공유 `.remember/remember.md`를 루프가 쓰지 않는다.** (2026-08-09 사용자 판정)

- **`<slug>`** = canonical ledger 문서 파일명에서 날짜 접두를 뗀 값(이 트랙이면 `ledger-handoff-mockup-nudge`). 트랙마다 다르므로 파일명 자체가 소유자다.
- **4섹션은 그 파일의 골격이다.** **D2 개정** — 원안은 "공유 파일 안의 *블록* 골격"이었다. 취지(**공유 remember.md의 트랙 인계·백로그에 이 골격을 강제하지 않는다**)는 그대로 살아 있고, 분리로 오히려 더 확실해진다.
- **D9 개정** — 원안의 "덮어쓰기 전 보존 확인 = 블록 교체"는 **불필요해진다.** 루프가 공유 파일을 아예 건드리지 않으므로 F3 사고(공유 파일 전체를 루프 상태로 덮어씀)가 **구조적으로 차단**된다. (**D15** 유지: 이 조항은 review-loop 전용이며 `ui-mockup:56`의 유사 조항과 지키는 대상이 달라 공통 규약으로 승격하지 않는다.)
- **`--resume` 대상 선택** = `.remember/loop-*.md` 조회. **0개 → 새 루프(빈 ledger로 시작)** · **1개 → 그 파일** · **2개 이상 → fail-closed 사용자 확인**(파일명이 트랙을 보여주므로 선택이 결정적이다). 텍스트 경계 파싱도, 저장값을 기대값으로 되쓰는 자기참조 대조도 없다.
- **성공 종료 시 파일을 제거한다**(§3 종료 전 커밋 시점) — 남아 있는 `loop-*.md`는 항상 미완 루프의 것이다. 다음 단계 인계는 이 파일이 아니라 공유 `remember.md`가 받는다.
- **채택 이유** — 이 규격은 R1~R4·C1의 **5개 라운드 연속으로 결함을 냈고**(fp-S2 경계 → fp-S4 소유권 → fp-S6 복원 선택 → fp-S4 재분류 소유자 키 → fp-S7 기대값 독립 입력원 · fp-S8 delimiter 충돌), 원인은 전부 **"공유 파일 안에서 블록을 텍스트 규칙으로 식별"** 이라는 한 지점이었다. 파일 분리는 그 부류를 통째로 없애고 **D23·D25·D27·D28을 철회**시킨다(규칙 4개 → 위 5줄). 브리프 G1·G2(과설계 금지)와 정합이다.
- **철회 항목**: **D23**(컨테이너 heading 경계·0개/복수) · **D25**(소유자 대조) · **D27**(블록 최대 1개·복원 선택) · **D28**(소유자 키에 ledger 경로) — 전부 D29가 대체한다(SUPERSEDED). 이 중 D27·D28은 사용자 판정이었고, **같은 사용자 판정으로 대체**됐다.

- **D22. 현행 복원 필드 `ledger(미확인 FIXED 큐 명시 포함)`는 ③에 통째로 남는다.** ③을 "미확인 FIXED 큐 + 미판정 blocking"으로 좁히면 배치가 아니라 **목록이 줄어** 위 계약이 문면에서 깨진다. 특히 **FIXED 큐는 비었는데 루프 직접 판정(ACCEPTED/OUT_OF_SCOPE/DEFERRED_TO_IMPL/DUPLICATE)만 있는 상태**에서 ③이 "해당 없음"이 되면, 재개 세션이 확인 필수 조건(§확인 모드)을 잘못 계산해 **감사 없이 빠른 종료**한다. ledger 본문은 단일 원본(phase 산출물 문서 말미)이 계속 갖고, ③은 그 위치와 루프 직접 판정 목록을 담는다(§복제 금지와 무충돌).

### C-8. 훅 재넛지 — 구간 기반

`hooks/scripts/context-threshold-hook.mjs`의 `decideNudge`를 1회 플래그에서 **구간 인덱스**로 바꾼다.

- **D4.** 넛지 지점 = `threshold + k × 0.15` (k = 0, 1, 2, …) — 간격 **15%p 고정**, 기본 임계 40%에서 **40 → 55 → 70 → 85%**. 임계 비례 산식은 케이스만 늘리므로 쓰지 않는다.
- **D5. 상한을 두지 않는다** — 구간이 오르는 한 계속 넛지한다. 100%를 넘는 구간은 auto-compact가 임박한 구간이라 경고가 더 필요하고, 상한이 없으면 산식도 하나 줄어든다.
- 현재 구간 `k_cur = floor((ratio − threshold) / 0.15)`. **`lastNudgeStep`이 `null`(아직 넛지 없음)이면 `k_cur ≥ 0`에서 넛지**하고, 값이 있으면 **`k_cur > lastNudgeStep`일 때만** 넛지한다.
- **D30. 구간 계산은 정수 스케일로 한다** — 위 산식을 부동소수점 그대로 구현하면 **D4가 명시한 70% 넛지가 실제로 누락된다.** `(0.70 − 0.40) / 0.15 = 1.9999999999999996` → `floor` = **1**이라 `lastNudgeStep = 1`(55%에서 넛지)일 때 `k_cur > lastNudgeStep`이 거짓이 된다. 115%도 `4.999999999999999` → 4로 오분류된다(실측 2026-08-09 node 확인). 따라서 **퍼센트 정수로 환산해 계산한다**: `k_cur = floor((round(ratio×100) − round(threshold×100)) / 15)` — 같은 입력에서 `1·2·3·4·5`가 정확히 나온다. 커스텀 `CLAUDE_CTX_THRESHOLD`에도 같은 환산을 적용한다.
- 플래그 파일에 마지막 넛지 구간 `k`를 저장한다 — 형식은 `step=<k>`(현행은 `"1"` 고정). 인터페이스는 `alreadyNudged: boolean` → **`lastNudgeStep: number | null`**.
- **D6. 재넛지(k ≥ 1) 문구는 지시 내용을 바꾸지 않고 사실만 더한다** — 해야 할 일(핸드오프 작성 + `/clear` 안내)은 첫 넛지와 같고, "이전에 안내했고 지금 N%다"를 덧붙인다. 이미 핸드오프를 썼다면 무해하도록 조건부로 쓴다. "즉시 종료하라"로 강도를 올리지 않는다 — 한 번에 끝내야 하는 정당한 장기 배치를 중단시킬 위험이 있다. 첫 넛지 문구는 현행 유지.
- **D3. review-loop 문면은 건드리지 않는다** — §2i는 이미 "Stop 훅이 넛지하면"으로 쓰여 있고 재넛지도 넛지다. 훅만 고치므로 C-4 개정과 범위가 섞이지 않는다.
- **D24. 사용률이 구간 2단 이상 떨어지면 새 주기로 보고 `lastNudgeStep`을 초기화한다** — `k_cur ≤ lastNudgeStep − 2`이면 `lastNudgeStep`을 `null`로 되돌리고 그 호출부터 다시 `k_cur ≥ 0` 규칙을 적용한다. **플래그는 session_id 기준인데 auto-compact는 session_id를 유지하므로**(`:66` `flagPath` · `:106`), 이 규칙이 없으면 85%까지 넛지한 세션이 compact로 20%까지 떨어져도 `k_cur > 3`이 될 때까지 — 즉 **사용률 100%까지 재넛지가 영구히 사라진다.** C-8이 없애려는 "임계 이후 무경고"가 compact 주기마다 그대로 재발한다(§1 C-8 행이 지목한 실패가 새 주기로 옮겨갈 뿐이다).
  - **2단(= 30%p) 하한을 두는 이유**: 1단 하락이나 임계 경계의 미세 진동(40% 넛지 직후 39%)까지 새 주기로 보면 그 경계에서 매 턴 재넛지한다. 판정 단위로 **구간을 그대로 재사용**하므로 상수가 늘지 않는다(D4의 `0.15`가 여전히 유일 상수).
  - 이 규칙은 **D5(상한 없음)와 무관하다** — 상한이 아니라 **주기 경계**를 정한다. D4의 간격·D6의 문구도 불변.
  - **D26. reset은 영속 상태에도 반영한다** — `decideNudge`는 넛지 여부와 함께 **다음 영속 상태**(`nextStep: number | null`)를 반환하고, `main`은 **넛지하지 않는 호출에서도** 그 값이 현재 플래그와 다르면 기록한다(`null` = **플래그 파일 삭제** — "파일 없음 = 아직 넛지 없음"이라는 현행 표현을 그대로 쓴다). 현행 `main`은 넛지할 때만 플래그를 쓰므로(`:114~117`), reset이 순수 함수 안에서만 일어나면 **다음 호출이 옛 `step`을 다시 읽어 reset이 무효**가 된다. 실패 예: `40→55→20→40→55`에서 20% 호출이 `step=1`을 남겨 두 번째 주기의 40%·55%가 모두 억제되고 **70%까지 무경고**다.
- 구버전 플래그 파일(`"1"`)은 `step=` 형식이 아니라 파싱에 실패하므로 **`lastNudgeStep = 0`으로 간주**한다 — 첫 넛지는 이미 한 것으로 보고 다음 구간부터 재넛지한다.
- `computeContextUsage`·임계 해석(`CLAUDE_CTX_THRESHOLD`)·`stop_hook_active` 처리는 불변. 간격 0.15는 상수.
