관찰:

1. **harden은 접촉 표면이 없어도 짧아지지 않았다.** 08-08 D6의 근거는 「접촉 표면이 없는 트랙은 갭 대장 자체가 작아 자연히 짧아진다」였는데, 5줄 수정(1.1.1)의 갭 대장이 22건·29분, 1.2.1이 30건·82분이다.
2. **결함 수정 트랙의 harden 질문은 사실상 사람이 답하지 않았다.** 1.3.3·1.3.4·1.3.5의 상태 줄은 「harden 판단 갭 = 사용자 지시로 메인이 추천안 입력」이다. ops-hub 실사용에서도 harden 추천 수용 95%(169/177 — OPSHUB2 §3), 무인 결정 번복률 2.4~5.5%·배포 후 결함 0(UNATTENDED §0). harden의 가치 근거(L4 — 사람만 아는 요구·제품 지식)가 이 트랙들에서는 행사되지 않았다. **단 harden이 이 트랙들에서 만든 결정(예: 1.3.1 D26~D34)이 없었다면 무엇을 놓쳤을지는 §6에서 쟀고, 결과는 「생략」 기각이다**(§6a — 사람·제품 지식이 필요한 결정이 트랙당 평균 2.67~3.67건).
3. **단계마다 세션이 바뀐다.** 경량 트랙도 spec·harden / 4 / 7 / 8 / 9가 각각 별도 세션(오케스트레이터 운영이면 별도 트랙 터미널 + 프롬프트 파일 작성 + 메인의 ④ 직접 검증)이다. 사용자는 2026-10-22부터 결함 수정 트랙을 「단계 경계 확인 없이 이어서 기동」하도록 지시해 운영 중이다(메모리). **→ §6b: 그 운영에서 단계 사이 공백은 1~3분이다 — 시간은 경계가 아니라 단계 안에서 간다.**
4. **세션 경계의 원래 근거는 컨텍스트 크기였다**(dev-cycle 문면 「컨텍스트가 커지고 phase가 섞인다」 · 07-11 설계 「컨텍스트 40% 핸드오프 넛지와 정합」). Claude 5 계열의 컨텍스트 윈도는 1,000,000이다(doctor SKILL.md — Claude Code 2.1.226 실측). 초안은 「경량 트랙의 7·8 두 단계는 그 40%에 닿지 않는다」고 가정했으나 **§6b에서 반증됐다** — 1.3.x 크기 트랙은 단계 하나가 이미 28만~39만 토큰이다.
5. **orchestrate 모델표가 낡았다.** `claude-fable-5-1` 고정 — 사용자 세션이 Fable 5.2로 바뀐 뒤에도(2026-11-12) 프로젝트 규약이 따로 정하지 않으면 트랙이 5.1로 뜬다.

**귀결(2026-11-12)** — 관찰 1·2 → §6a(harden 「생략」 기각 · 축약형은 harden 질문 방식 트랙으로, D1·D2) · 관찰 3·4 → §6b(연속 진행의 전제 반증, D3) · 관찰 5 → 이 트랙의 유일한 변경(§3c, D4).

- **기각 근거**: §6 회고 실측에서 사람·제품 지식이 필요한 harden 결정이 트랙당 평균 2.67~3.67건(사전 등록 기준선 1건 이상) → 「생략」 기각, 「축약형」(§6a).

- **넘기는 재료**: §1 관찰 1·2 · §6a 전체(특히 사후 관찰 — 「결함 수정」으로 불린 트랙 6개 중 5개가 새 동작 결정을 품었다) · eval `data/harden-retro-2026-11-12/`.

### 3b. 경량 구간 연속 진행 — 이 트랙에서 제외 (2026-11-12 harden 판정 기록)

- **초안의 제안**: 경량 트랙이 spec 확정 뒤 4(수행 시) → 7 → 8을 한 세션에서 이어 진행한다 — dev-cycle(§핵심 원칙·§단계 경계·§하지 말 것) · review-loop §4 끝 안내 · orchestrate SKILL.md ①·④ · 트랙 프롬프트 템플릿 §5·§7·§8 · README 3종 변경.
