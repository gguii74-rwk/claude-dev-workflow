## 1. 문제 (실측 근거)

C-6 impl 루프에서 같은 구조 표면의 finding이 반복됐다:

- **계열 A (경량 승인 상태) 5회** — fp-I6·I8·I10·I12·I13. 경로 판정(세션 한정·휘발)과 생략 기록(spec D번호·영속)이 같은 평면에 놓여 경계 문장으로 봉합됐고, 상태 전이마다 구멍이 났다. 사용자 재결정 2회(영속화→세션 한정 전환·기록 존중 경계)를 거쳐 fp-I12·I13은 **ACCEPTED**로 닫혔으며 그 보완 귀착지가 이 트랙이다. 기준선: R-skip4 잔존 이탈 **1/6**(방향은 fail-closed — 배치 232런에서 검증 생략 방향 이탈 0건).
- **계열 B (③ 조건 조합 미포괄) 3회** — fp-I1(plan 있음+ledger 미종결)·fp-I9(5 생략+6 무기록)·fp-I11(4만 생략+5·6 유지). 매 라운드 다른 조합이 열거의 구멍으로 드러났고 국소 수정으로 닫았다. 당시 사용자 판정: 재구성은 범위 초과라 보류, 잔여 리스크로 명시 — "상태 차원이 늘면 또 다른 미포괄 조합이 나온다."

**수렴 관찰**: 위 국소 수정들(fp-I1 조건 추가·fp-I9 자동 해당없음·fp-I11 조건식·fp-I14 일반화)은 전부 "**가장 이른 미완·비생략 단계로 보낸다**"는 암묵 규칙을 조각조각 문면화한 것이다. 이 규칙을 명시 구조로 올리면 미포괄 조합 계열이 정의상 사라진다 — 모든 단계에 완료/해당없음 판정이 있으면 "첫 미완 단계"는 항상 유일하다.

## 3. 설계

### 3a. 경량 경로 절 — 상태 계층 정의

절 앞머리에 계층 표를 신설하고, 기존 규칙을 내용 그대로 각 계층 아래로 재배치한다:

| 계층 | 내용 | 수명 | 판별이 다루는 법 |
|---|---|---|---|
| 세션 상태 | 경량/정식 판정·승인 | `/clear`에서 소멸 | 추정 금지, **재확인**(미확인 기본값 = 정식) |
| 문서 기록 | 생략·철회·승격 사유(spec D번호) | 영속 | **존중** — 재확인 대상 아님. 철회분은 불인정 |
| 산출물 | spec·plan·ledger 존재/종결 | 영속 | 단계 상태 판독 신호 |
| 하한 3종 | spec 문서·3 harden-spec·8 impl 루프 | 불변 | 기록으로 덮지 못함(생략 기록 무효) |

- 기존 44행의 판정 규칙(지도 1차 + 확인 1회, 승인 시만 경량, 거절·무응답·모호 = 정식)은 '세션 상태' 아래로 이동, 내용 불변.
- fp-I13의 봉합 문장("재확인 대상은 아직 수행하지 않은 단계…")은 **삭제하고 계층 정의의 귀결로 대체** — 재확인은 세션 상태에만 적용되고, 문서 기록은 정의상 재확인 대상이 아니다.
- 승격(D4)·생략 기록(D2)·하한(D3) 항은 각자 계층 아래 재배치, 내용 불변.

### 3b. 판별 절 — 단일 규칙 + 단계×신호 표

열거 7항(③)과 ①·② 절차 서술을 다음으로 대체한다:

> **판별 규칙**: 1→9 순서로 각 단계의 상태를 판독해 **첫 미완 단계 하나만** 안내한다(C-10 D16 — 별도 안내 원칙 문장을 두지 않는다). 단계 상태 = **완료**(산출물 신호) ∨ **해당없음**(유효한 문서 기록 — 철회분 불인정) ∨ **미완**. 신호는 문서 조회(grep 수준)로 본다.

**단계×신호 표 (문면 초안 — 구현에서 최종 문구 확정 · 형식 = markdown 표, C-10 D11)**. 파일럿 게이트(C-10 D11): arm당 1런 파일럿에서 표 오판독 기인 이탈이 관측되면 열거형 불릿으로 폴백한다.

| 단계 | 완료 신호 | 해당없음 조건 | 미완 시 안내 |
|---|---|---|---|
| 1–2 | `docs/specs/<feature>` 존재 + 6항목 골격(부분 결손은 3행 소관 — C-10 D14) | **없음(하한 — spec 문서)** | brainstorming (+착수 브리프) |
| 3 | 재논의 금지 블록 + D번호 결정·근거 실재 + 6항목 내용 기준 충족(D21) | **없음(하한)** | harden-spec |
| 3.5 | spec `## UI 설계` 섹션 + 목업 경로 실재 | 비대상(화면 무관) 또는 명시 생략 기록 | ui-mockup |
| 4 | spec ledger 종결 | 유효 D번호 생략 기록 | review-loop(spec) |
| 5 | plan 존재 | 유효 D번호 생략 기록 | writing-plans-split |
| 6 | plan ledger 종결 | **5가 해당없음이면 자동**, 또는 유효 기록 | review-loop(plan) |
| 7 | 구현 완료 | — | plan 있으면 SDD, 5 해당없음이면 직접 구현(TDD) |
| 8 | impl ledger 종결(plan 말미 · planless는 spec 말미) | **없음(하한)** | review-loop(impl) |
| 9 | PR merged + repo 규약 후속 | — (경로 무관 공통) | finishing + repo 규약. 완료면 **"트랙 완료"** |

- spec 게이트 6항목의 **내용 기준** 확인(D21)은 1–2행(골격)·3행(내용 완전성)의 완료 신호로 **분담**(표제 일치 아님).
- 6항목 부분 결손 분기(C-10 D14): spec 파일 부재·골격 부재(대부분 항목이 빈 껍데기) → **1–2행 미완**, 파일 존재 + 일부 항목 내용 결손 → **3행 미완**(harden-spec이 질문으로 메움) — 위 1–2·3행 완료 신호에 직접 encode: 1–2 완료 = 골격 기준이므로 첫 미완 규칙이 부분 결손을 1–2로 보내지 않고, 3행이 내용 완전성으로 받는다(현행 "1–2 또는 3"의 기준 미정의 해소).
- 하한 행의 해당없음 열 부재가 곧 ①의 하한 가드다. fp-I10ⓐ·fp-I14의 "첫 미완이 8보다 먼저" 예외는 규칙 자체가 되어 소멸한다.

**규칙 밖 가드 3종** (표 판독의 전제, 별도 문단 유지):
1. **fail-closed** — 신호가 불명확하면(6항목 내용 불명·harden 실행 불명·repo 밖 사실) 통과시키지 않고 사용자 1회 확인.
2. **비소급(결과 기준 — C-10 D10)** — 되돌림이 **종전(0.10.0) 판별과 다른 결과**에 기인할 때만 legacy 확인 1회(기존 트랙이면 종전 판별). 의미 불변 이식 지점은 종전 규칙 취급(비소급 불요) — 규칙명 열거 방식은 폐기한다. 8은 종전 판별에도 있으므로 비소급이 8을 건너뛰는 근거가 되지 않는다.
3. **세션 상태 재확인(C-10 D13)** — 세션 상태가 판별 결과를 가를 때만(트랙이 경량 운영을 시사·명시하는데 미기록 생략 결정이 걸릴 때) 그 세션 1회 확인. 그 외에는 질문 없이 기본 정식(3a 계층 규칙 · C-P arm 기대 동작).
